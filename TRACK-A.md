# TRACK A — "timbre" · instruments and effects

Branch: `claude/timbre` · Worktree: `.claude/worktrees/timbre`

You are one of three parallel tracks closing INCDAW's gap against FL Studio.
The full re-audited gap list is `docs/FL2026_GAP.md` §3; this brief is your
slice of it. The other two tracks are `arrange` (playlist and automation) and
`bridge` (hardware, hosting and files). You will not need their files.

## What this track is for

INCDAW's mixer and sequencer are further along than the sounds they carry.
There are three instruments — Sampler, Reference Synth and the new INCDAW
Piano — and no synthesis beyond them, and the effect rack has the working
tools but none of the shaping ones. This track fills the catalogue.

The bar is CLAUDE.md §13/§14: build the framework once, then the instruments.
`engine::Instrument` and `engine::dsp::BuiltinEffect` already exist and both
catalogues are single tables that the compiler, the parameter registry and the
UI all read — adding an entry must not require special-casing anywhere. That
is the existing exit criterion and it holds for everything you add.

## The work, in order

### A5 — the preset system (do this first)

Everything below is worth more with presets and worth less without them, and
it is the one item that changes a shared shape, so it should land before the
instruments pile up.

A channel's instrument parameters persist as `ChannelInstrumentParameter`, and
an effect's persist inside its state blob. Neither is a *preset*: nothing can
be named, saved, recalled onto a different channel, or shipped as a factory
default. Build that: a preset is a uid plus a set of {parameter id, value},
versioned, stored as a file under Application Support (the theme library in
`src/ui/ThemeLibrary.h` is the pattern to copy — a folder of versioned JSON
files the user owns, named by the file), with factory presets compiled in.

Definition of done: save, load, rename, delete and duplicate a preset for any
builtin instrument or effect; factory presets for everything in both
catalogues; the parameter panel and the Tone panel both grow a preset control;
loading a preset is one undo entry.

### A1 — wavetable synth

Wavetable oscillator with a table position parameter, band-limited playback
(mipmapped tables or equivalent — aliasing is the whole difficulty), at least
two oscillators, sub, filter, two envelopes and two LFOs through the existing
modulation shape. Ship a set of original single-cycle tables generated by code
rather than bundled as content (§20/§43 forbid bundling recorded content).

### A2 — FM synth

Four to six operators, an operator matrix rather than fixed algorithms, per
operator ratio/fixed frequency/level/envelope, feedback. The piano's electric
voicing has an FM tine inside it; do not reuse that code — it is voiced for a
tine and belongs to the piano.

### A4 — drum machine / pad instrument

Sixteen pads, each a sample or a synthesized voice, per-pad tuning, envelope,
filter, pan, output routing and choke groups. This is the FPC/Drumaxx-shaped
gap: the Sampler has zones and layering but nothing pad-oriented, and the
Channel Rack's step grid is the natural front end for it.

### A6 — multiband compressor

Three or four bands over Linkwitz-Riley crossovers, each band with the
existing compressor's law, per-band solo and bypass, and — the requirement
that makes it honest — the crossover network must sum to unity so the
defaulted plugin nulls against its input like every other effect here.

### A7 — de-esser

Split-band or wideband-with-sidechain-filter; the detector path is already
proven by the sidechain work in the compressor.

### A8 — stereo imaging insert

Mid/side width, per-band width, mono-below-frequency, correlation meter.
Strip-level stereo separation already exists (`MixerNode`); this is the insert
version with a picture.

### A9 — waveshaper with a drawable curve

`incdaw.saturator` is a tanh and a mix. Replace nothing; add a shaper whose
transfer curve is a user-drawn spline, with oversampling.

### A10 — parametric EQ, more bands and a draggable curve

The Tone panel (`src/ui/macos/TonePanel.mm`) already plots the response from
`engine::dsp::eqMagnitudeDb`, which designs its biquads with the code the
audio thread runs. Extend the EQ to N bands with selectable types, and make
that curve draggable — grab a band on the plot and move it. Keep the
"the picture cannot disagree with the filter" property; there is a test for it.

### A11 — convolution reverb

Partitioned uniform-block convolution (the FFT is in `engine/dsp/Fft.h`),
impulse responses loaded from the user's own files through the browser. Ship
no IR content; generate a couple synthetically if a default is wanted.

### A12/A13 — vocoder, and time/volume gating

Lowest priority. A13 is the Gross Beat-shaped gap: a bar-synced curve editor
driving time and volume. Do not start either until A1–A11 are done or you have
reported why.

## Definition of done for this track

Every instrument and effect: in its catalogue table, automatable through the
parameter registry with no special case, state saved and reloaded, bit-exact
bypass at its transparent settings where that is meaningful, a null test and
an independently-written reference test, realtime-safe, and a CHANGELOG entry.

## Working rules (identical for all three tracks)

**Your branch.** You work in this worktree, on this branch, and nowhere else.
Push after every commit — `git push origin <this branch>`, **never to `main`**.
The global "push to main after every patch" note does not apply here; main is
where the three tracks get merged, one at a time, by the user.

**Never stage by wildcard.** No `git add -A`, no `git add .`, no `git commit -a`.
Stage the exact paths you changed. Two sessions once shared one working tree in
this project and swept each other's half-written work into unrelated commits;
that is why this rule is written down.

**File boundaries.** Each track owns a disjoint part of the tree (below). Four
files are shared choke points and every track has to touch them:

- `src/CMakeLists.txt`, `tests/CMakeLists.txt` — add your source lines only,
  next to the neighbouring ones. Never reorder or reformat.
- `CHANGELOG.md` — add your entry under `## [Unreleased]`. Do not touch
  released sections.
- `src/ui/macos/main.mm` — the shell. Additive only: your menu item, your
  window, your command registration. Never restructure what is there.

If the work needs a file another track owns, **stop and report it** rather than
editing across the boundary. That is a merge conflict with a person's name on
it, not a code problem.

**The process still applies** (CLAUDE.md §38–§44). The scope in this brief is
pre-approved; individual items inside it are not a licence to skip the rest:

1. Consult the graph first — `graphify query "…"` — before reading files.
2. Smallest coherent increment, then build, then tests.
3. `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug`
   `cmake --build build -j8` — the tree builds with `-Werror`; warnings are errors.
4. `./build/tests/incdaw_tests` — every case green before you commit.
5. New behaviour needs new tests. A DSP block needs a null test at its
   transparent settings and a reference implementation written independently
   of the class under test (see `tests/unit/BuiltinEffectTests.cpp`).
6. Realtime contract: no allocation, no locks, no file or network I/O and no
   unbounded work on the audio thread.
7. `graphify update .` after meaningful source changes, committed with them.
8. A CHANGELOG entry per increment.
9. Project format changes bump `INCDAW_PROJECT_VERSION` and ship a migration —
   an old project must still open.

**Already done for you.** `third_party/clap/clap` is not in git and has been
copied into this worktree; do not delete it and do not commit it.

**Ordering.** The items in your list are ordered. Do them in order unless one
is blocked, and say so if you reorder.
